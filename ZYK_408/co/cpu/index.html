计算机组成原理：CPU与流水线

5.1 CPU的功能和基本结构

寄存器的任务先分清

寄存器 本章主要用途 易混点
PC 指示取指地址与控制流位置 与IR不同
IR 保存当前指令、提供译码字段 不是下一条指令地址
MAR 保存访存地址 位数联系可寻址单元数
MDR 暂存访存数据 位数联系数据通路宽度，不等于地址位数
通用寄存器 操作数、结果或地址 同一寄存器内容如何用由指令决定
PSW/标志 状态、条件等 具体内容由ISA规定

取指可抽象为，发读请求，存储内容经数据通路进入IR，并更新PC。是否能同时完成、需几个周期，取决于图和时序条件。

5.2 指令执行过程

取指周期取得指令并更新PC，间址周期按寻址方式取得有效地址，执行周期完成指令功能，中断周期完成中断响应入口操作；不是所有指令都经历每一种周期。指令周期由若干时钟周期组成，多周期实现的不同指令所需周期数可不同。PC的增量由指令长度与编址单位决定，不能无条件写成1或4。

5.3 数据通路的功能和基本结构

数据通路题：先写语义，再沿图走

例： load的语义是“基址+偏移求EA，读内存，结果写目的寄存器”；store是“求EA，把源寄存器数据写到内存”，没有把结果写回通用寄存器这一步。

图源：强化讲义PDF第135页。MUX选路、加法器相加、ALU按操作控制产生结果。控制信号决定选择和写入，但数据沿数据线传递。

按这个顺序填控制表：

  1. 列出读哪些寄存器、写哪个寄存器、是否访存。
  2. 确定ALU的两个输入和运算。
  3. 确定写回来源是ALU、存储器还是其他来源。
  4. 确定PC顺序前进还是分支/跳转。
  5. 给MUX选路、寄存器写使能、存储器读写、ALU控制赋值。

无关信号才可写X。例如不写通用寄存器时，写回MUX可能无关；但MemWrite若随意写X，可能产生意外存储，不能因为“该指令不访存”就把它当无关。

单总线、多周期：先检查资源冲突

单条内部总线同一时刻通常只能由一个源驱动，多个目的寄存器可在条件允许时同时接收同一个值。ALU要做双操作数运算时，常需要暂存器保存一个输入。

排微操作步骤：写出不可省的操作 → 标依赖 → 检查总线谁输出、谁接收 → 标访存等待 → 再合并能并行的步骤。不能把同一条总线安排成“R1输出A、R2同时输出B”。

单总线微操作的可执行性

先给每个时钟列一个总线源；多个寄存器可接收同一个值，但不能让两个不同源同时驱动单总线。若ALU一端接暂存器Y、另一端接总线，执行R1←R2+R3可排：T1为R2out,Yin；T2为R3out,ADD,Zin；T3为Zout,R1in。若图有PC专用加法器，PC递增可能并行；若PC递增也要借用同一ALU，则必须排开。把控制信号写对还不够，需检查数据沿图确实能到达。

从语义填单周期控制表

假定ALUSrc=1选立即数，MemtoReg=1选内存，RegDst=1选rd。

指令 ALUSrc MemRead MemWrite RegWrite MemtoReg RegDst ALU功能
add 0 0 0 1 0 1 加
lw 1 1 0 1 1 0 加，形成EA
sw 1 0 1 0 X X 加，形成EA
beq 0 0 0 0 X X 减，判断相等

sw不写通用寄存器，所以写回MUX可无关，但MemWrite必须为1；beq的MemWrite必须为0。如果题图规定相反的MUX编号，要翻转对应选择位。强化讲义PDF第141—143页可对照数据流；第158页把beq列入WB不能理解为实际写回通用寄存器。

单周期时钟由最慢完整路径决定

若取指200ps、读寄存器100ps、ALU150ps、数据存储器200ps、写回选择50ps，忽略其他延迟，则lw串行路径700ps。单周期CPU所有指令都使用至少700ps的周期；add少了数据存储阶段不表示它能自动缩短该CPU的时钟周期。流水化后要重新按阶段最大延迟加流水寄存器开销求周期。

5.4 控制器的功能和工作原理

控制器：机器指令与微指令不是同一层

硬布线控制通过组合逻辑、状态和时序等产生控制信号；微程序控制从控制存储器读取微指令，逐步给出控制信号和后继地址。微指令位于控制实现层，不是用户程序中的机器指令。

计算题：微指令字长=操作控制字段+判别字段+下址等字段；控存容量=微指令条数×每条位数。水平型可并行控制较多操作，字段编码可缩短字长但增加译码约束。填字段前先判断哪些微操作互斥、哪些可能同周期发生。

微指令字段编码的节省

若一组有5个互斥微命令，且允许本组全不选，需要6种状态，字段至少位。另两组有3和2个互斥命令，分别还需2、2位，总7位；若直接编码这10个控制命令，需要10位。字段分组必须保证同一字段内的微命令不会要求同时发出。控存有256条微指令、每条32位，容量8192bit=1KiB；8位微地址不是8字节控存。

5.5 异常和中断机制

分支、异常与并行概念

分支题先找比较和目标计算在哪一级完成、是否预测、预测失败冲刷哪些年轻指令。停顿和冲刷可能有重叠，不要把几个罚时数字重复相加。

异常由指令执行相关事件引起，例如缺页、非法指令、系统调用等；外部中断由设备或时钟等引起，与当前指令的执行一般异步。返回地址是重做当前指令还是继续下一条，由异常种类和体系结构规定。

超标量关注一周期发射多条指令；多核是多个处理核心；硬件多线程切换或交错线程以利用资源；它们不能互当同义词。

异常返回的三种位置

故障发生在指令完成前，可恢复时常重新执行故障指令，如缺页；陷阱在指令完成后报告，通常返回下一条，如某些调试/系统调用约定；终止类可能无法恢复。外部中断一般在指令边界响应。具体断点依ISA和题设，不能断言所有异常都返回PC+4。硬件一般保存必要断点/状态并进入处理入口；通用寄存器现场常由软件按需要保存。

5.6 指令流水线

流水线：跨指令重叠，不保证单条更快

典型五段为IF取指、ID译码/读寄存器、EX执行、MEM访存、WB写回。不是每条指令都做实际内存读写，也不是每条都有通用寄存器写回。

图源：强化讲义PDF第157页。横向看一条指令经历阶段，竖向看同一周期不同指令争用哪些资源。原图中的无冲突排布是理想示意，遇到相关要重新插入停顿。

图源：强化讲义PDF第159页。注意阶段间的寄存器：它们保存跨周期使用的数据和控制信息。读图要跟踪同一条指令的数据，避免把后一条指令当前的字段误用于前一条指令。

理想段流水线、每周期、连续执行条且无停顿：

周期通常取最慢一级组合延迟加流水寄存器开销。若另有个未重叠停顿周期，则常写。吞吐率为，稳态上限约；与非流水比较的加速比要先写清比较基准。

冒险题：结果什么时候产生，下一条什么时候需要

类别 冲突来源 典型处理
结构冒险 同周期争同一硬件 增加资源或停顿
数据冒险 后指令要用尚未可用的数据 转发、停顿、合法调度
控制冒险 分支结果/目标尚不确定 停顿、预测、冲刷等

RAW题的标准动作：给每条指令列“读寄存器、写寄存器” → 找依赖 → 标产生值的阶段末 → 标消费值的阶段 → 看是否有对应转发路径 → 不够才停顿。

在常见五段模型中，ALU结果EX末可用；load数据MEM末才可用。若下一条紧接着在EX需要load结果，即使有常见转发，也通常仍要停1周期；若图中有特殊路径或不同使用阶段，结论会变化。

示例：常见EX/MEM与MEM/WB到EX转发：

周期 1 2 3 4 5 6 7
lw IF ID EX MEM WB
add IF ID 停顿 EX MEM WB

load在第4周期末得到数据，add第5周期EX使用。若不支持转发，还要按寄存器写回与读取时序重新算，不能照抄一个停顿。

精确到周期的冒险分析

以五段、寄存器同周期先写后读、有MEM/WB和EX/MEM到EX转发为前提：ALU→ALU通常不用停；lw→紧随ALU停1周期；若lw后的寄存器仅作sw的数据且有直达MEM的转发，可能不用停。若该值是sw的基址，EX就要用，仍须检查load-use。判断来自“何时产生、何时使用、可否到达”，不来自相邻指令名字。

无转发时，紧邻add的消费者须等写回：生产者周期5 WB，消费者可周期5 ID、周期6 EX，因此消费者在ID多停2周期。若不允许同周期先写后读，再多停1周期。

分支罚时与平均CPI

基准CPI=1，分支占20%，预测错误率10%，每次错误罚3周期，则仅分支引入0.2×0.1×3=0.06，平均1.06。若另有load-use停顿，只有在两种罚时互不重叠且题设允许相加时才继续累加。理想n+4只负责装入排空，不能又给每条指令加5。

5.7 多处理器的基本概念

并行题分清对象

SISD是单指令单数据；SIMD对多数据执行相同指令，适合向量化；MIMD让多个处理单元独立执行不同指令流。多核可组成共享内存多处理系统，但每核有私有Cache时需维护一致性。硬件多线程改善资源利用与隐藏等待，不保证单线程延迟下降。超标量是动态多发射的一类；VLIW通常由编译器静态组织并行操作，不能把“每周期多条”都归于同一种调度机制。
