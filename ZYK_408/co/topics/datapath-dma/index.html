计算机组成原理：数据通路、总线与DMA：带图综合题

1. 读单总线图：先认方向，再认锁存条件

图源：王道PDF物理页221，书内209页。沿图确认：寄存器out驱动总线，in允许锁存；Y保存ALU一侧操作数，另一侧来自总线；ALU结果先入Z，再由Zout送总线。MDR连接内部通路与主存读写通路，MAR保存访存地址。图中系统总线与内部总线不是同一组线，不能因为名字都叫总线就认定全部操作必然互斥。

例1：LOAD R1,[R2]的执行段控制表

另设本题主存读取需3拍：读请求发出后，连续3拍Read有效，第三拍末MDR从外部存储通路锁存数据。MAR已保存地址；这3拍不使用内部总线返回数据。忽略取指，R2为有效地址。

拍 有效信号 结束后的关键状态
E1 R2out、MARin MAR←R2
E2 Read 访存第1拍
E3 Read 访存第2拍
E4 Read、外部读入MDR使能 MDR←M[MAR]，第3拍结束
E5 MDRout、R1in R1←MDR

需5拍。这里外部读入MDR使能与内部总线MDRin应按图中器件接口区分；若试题另有MFC完成握手，用其结束等待。R1只能在数据准备好后取得读值。若改成STORE [R2],R1，必须先准备MAR与MDR的写数据，再发写请求，不能把LOAD的表只换Read为Write而不改数据来源。

例2：如何判断新增指令能否只改控制

现有通路支持R3←R1+R2，若ALU已有减法且输入通路不变，增加R3←R1-R2通常可复用Y、ALU、Z，只增加/修改操作选择和控制序列。若要新增R3←M[R1]+M[R2]，同一单端口主存不能同时读两个地址，需要分次读取并保存第一个值；若又要求一拍完成，现有资源显然不满足。

答题顺序：写语义 → 标输入来源和结果去向 → 查所需运算功能 → 查同拍端口与总线冲突 → 判断缺控制还是缺硬件。不要看见新操作码就必然回答新增ALU。

2. 带MUX的单周期控制题

数据通路如下：双读单写寄存器堆，数据存储器独立；PC顺序更新用独立加法器。WB选择0为ALU、1为存储器；B选择0为寄存器rt、1为符号扩展立即数。取指通路略。

例3：ADD、LOAD、STORE填表。目的寄存器编号由指令编码或额外选择逻辑提供。

指令 B选择 ALU MemRead MemWrite WB选择 RegWrite
ADD rd,rs,rt 0 加 0 0 0 1
LOAD rt,imm(rs) 1 加 1 0 1 1
STORE rt,imm(rs) 1 加 0 1 无关 0

STORE中B选择立即数用于算地址，但存储器写入数据仍是读B端口的rt值。观察两条分支线即可解释为何“ALU取立即数”和“往主存写rt”能同时成立。添加立即数加法只需B选1、ALU加、WB选0、RegWrite=1，并正确选目的寄存器；若立即数语义为零扩展而现有只支持符号扩展，还需补扩展选择。

最长路径题要串起真正经过的部件

若LOAD经过指令存储器200 ps、寄存器读80 ps、扩展与B选择合计40 ps、ALU120 ps、数据存储器250 ps、WB选择30 ps、写入设置20 ps，且本题明确这些延迟按顺序累计，则LOAD路径740 ps。若寄存器读与立即数扩展能并行，就不能盲加两条支路延迟，应按较晚到达ALU的输入计算；题图决定关键路径。740 ps对应上述串行路径。

3. 多发射：依赖和资源要同时满足

超标量动态多发射由硬件检查与调度；超长指令字VLIW主要由编译器静态安排可并行操作；超流水通过细分阶段缩短周期。多发射可能IPC>1、CPI<1，更多流水段本身不意味着一周期能发多条。

例4：给定资源与依赖，安排发射表

每周期最多顺序发射2条，有2个ALU、1个访存部件；ALU延迟1周期，load延迟2周期，store延迟1周期，部件均可接收本题所需新操作。结果在完成周期末产生，下一周期开头可用；同周期不能使用刚发射指令的结果。无重命名需求、无其他阻塞；第一条因依赖不能发射时，后面的指令也不能越过。

周期 发射 理由
1 I1、I2 无相互依赖，分别用访存部件和ALU
2 无 I1要到本周期末完成，I3不能发；顺序发射也挡住I4
3 I3、I4 r1和r3均可用，两个ALU足够
4 I5、I6 r6和r7已在周期3末生成，资源无冲突

6条用4个周期发射并按本题延迟在第4周期末全部完成，平均IPC=1.5。若硬件允许越过阻塞的I3发射I4，周期2可能被利用，但必须重做整张表；这是模型变化，不是看到空槽就能擅自移指令。若每周期只有1个ALU，周期3也不能同时发I3与I4。

乱序执行还需维护程序语义；寄存器重命名能缓解假相关WAR/WAW，不能消除真正RAW数据依赖。精确异常要求处理程序能够观察到与顺序执行相符的体系结构状态。

4. 异步握手图：撤销顺序也可能考

图源：王道PDF物理页297，书内285页。箭头表示一方动作依赖另一方信号：不互锁用预定延迟撤销；半互锁请求方等响应再撤请求，响应方按固定延迟撤响应；全互锁两边撤销都等待对方。别把“有没有公共时钟”和“有没有相互等待”混成一个判断。

例5：四阶段全互锁握手耗时

请求与响应每个信号单程传播10 ns；从设备收到请求后20 ns备好数据并发响应；主设备收到响应立即取数据并撤请求；从设备收到请求撤销立即撤响应；主设备收到响应撤销后可开始下一事务。每事务传4 B，不计额外仲裁。

首次取到数据40 ns，但相邻完整事务最小间隔60 ns。持续带宽4 B/60 ns≈66.67 MB/s；不能按4/40 ns算长期吞吐，因为复位阶段仍占时间。若协议允许流水事务重叠，需要另给规则，不能默认为可重叠。

分离式事务释放的是等待阶段的总线

请求阶段只发地址和命令，之后释放总线；从设备准备好时再争用总线返回响应。请求与响应通常带标识便于配对，不要求准备期间总线一直空闲，也不保证各响应顺序一定与请求顺序一致，按协议规则处理。

例6：单次读请求占10 ns，设备准备80 ns，响应传数10 ns。独占事务从头到尾占100 ns；分离式事务实际占总线20 ns，中间80 ns可用于其他事务。单个请求的最低响应延迟仍为100 ns，

5. 轮询开销：检查次数与设备产出次数未必相等

例7：定时轮询

设备每1 ms产生一个数据，接口只有一个数据缓冲；CPU每100 μs检查一次，一次检查20周期，100 MHz。每秒检查10000次，占200000周期，即CPU的0.2%。若每次真正读取和处理额外80周期，设备稳定每秒1000数据，则再占80000周期，总0.28%。不能把所有10000次检查都算成一次成功传输。

最坏轮询发现延迟接近100 μs，另加处理到读走的时间；这里可在下一1 ms数据到来前处理。若CPU一直忙等而没有用间隙做其他工作，即使每次检查只20周期，等待期间也不能全部算成对应用程序可利用的空闲时间。定时轮询与阻塞忙等是不同调度模型。

6. DMA争用：CPU管理开销、总线占用和实际停顿分别算

例8：每个DMA请求必然与CPU冲突的周期挪用模型

DMA速率10 MB/s，每次传4 B；每次独占主存总线100 ns。每秒有250万次传输，占总线0.25 s，即25%。若本题规定CPU在这些时段每次都需要主存且完全不能推进，CPU因此等待25%的墙钟时间。若CPU可执行寄存器运算、命中私有Cache或这些时段原本不访存，真实停顿可更少；“总线被占25%”本身不能直接推出所有程序慢25%。

题若给CPU任务有不重叠的有效工作时间0.75 s，DMA在整个执行期间稳定占25%且每次均阻塞有效推进，则实际完成时间 s。不能简单做0.75×1.25；等待比例的分母是最终墙钟时间。

例9：CPU与DMA交替访存的可行性

CPU每1 μs只需一次500 ns主存访问，剩余半周期可供DMA；若DMA每字需要500 ns且传4 B，固定交替时DMA峰值4 MB/s。若设备要求6 MB/s，这个固定时隙安排不够，须改变调度或提高带宽，不能说“DMA不执行CPU指令所以不受限制”。

DMA预处理设置起址、计数和方向；传送期间控制器更新地址与计数；块结束可发完成中断。DMA请求申请的是访存/总线使用权，完成中断请求的是CPU进入处理，两者时机与用途不同。
